## P2 (postdoc) — Neder gap ≤ 12 (`Proofs/Enumerative/NederGap.lean`)

The file is currently a 16-line stub with no content (lane killed at

**Goal.** Machine-check: the gap between consecutive Zumkeller numbers
(A083207) is at most 12.

**Route — Neder's own OEIS comment, NOT Rao–Peng.** The stub's old
Rao–Peng attribution is wrong for this claim; the proof is contained in
Charlie Neder's A083207 comment (Jan 15 2019), pinned verbatim
2026-08-05:

> The numbers 3 * 2^k for k > 0 are all Zumkeller numbers: half of one
> such partition is {3*2^k, 3*2^(k-2), ...}, replacing 3 with 2 if it
> appears. With this and the lemma that the product of a Zumkeller
> number and a number coprime to it is again a Zumkeller number (see
> A179527), we have that all numbers divisible by 6 but not 9 (or
> numbers congruent to 6 or 12 modulo 18) are Zumkeller numbers,
> proving that the difference between consecutive Zumkeller numbers is
> at most 12.

Re-pull the entry with `goof oeis show A083207` yourself and quote it
in the header. The coprime-product lemma is ALREADY IN-TREE:
`IsZumkeller.mul_of_coprime` in `Proofs/Enumerative/IsZumkeller.lean`
(sorry-free, reviewed). So the work is: (1) 3·2^k is Zumkeller for
k ≥ 1 (Neder gives the partition); (2) closure ⇒ every n ≡ 6, 12
(mod 18) is Zumkeller; (3) package as the gap theorem — state it both
as "every 12 consecutive integers ≥ 6 contain a Zumkeller number
divisible by 6" or the consecutive-difference form, whichever STYLE.md
and the existing IsZumkeller API make cleanest; prove the other as a
corollary if cheap.

## P3 (postdoc) — AdditionChain convention equivalence
(`Proofs/NumberComplexity/AdditionChain.lean`, extend in place)

**Goal.** Prove the file's permissive chain convention computes the
same minimum as A003313's ascending convention.

Existing API (verified 2026-08-05): `IsAddChain` is the permissive
inductive (any prior pair, repeats allowed; `example : IsAddChain
[2, 2, 1] := by decide` is a ground check), `AdditionChain n` is the
subtype with `c.head? = some n`, `chainSteps c = c.tail.length`, and
`l n = ⨅ c : AdditionChain n, chainSteps c.val` (noncomputable).

A003313's convention, pinned verbatim (M. F. Hasler, Nov 14 2025):

> An addition chain for n, of length r, is a finite sequence s with
> 1 = s(0) < s(1) < ... < s(r) = n and s(k) = s(l) + s(m) for some
> l, m < k, for all k <= r.

Define an ascending-convention predicate faithful to that (strictly
increasing, starts at 1, ends at n) and prove `l` equals the ascending
minimum. The module docstring already sketches the argument: sorting
and deduplicating any permissive chain yields an ascending chain of no
greater length (every element of a permissive chain is a sum of two
earlier-or-equal elements; after dedup + sort the witnesses still
precede). The converse direction is trivial (an ascending chain IS a
permissive chain, reversed into the list encoding).

Note: an INDEX claim that this agreement was "computationally verified
to n = 24" cites a review file that does not exist — treat it as
unsourced. Add a few `decide` ground checks (n ≤ 8 or so) as examples.
