## Lane model

- `prover` = Fable 5 xhigh. Use for items where the gap between
  "stated" and any known formal route is largest. Also good for
  follow-on results that require genuine mathematical insight (e.g.
  the defect exact identity, Sylvester-Schur). Not just for P3 tier.
- `postdoc` = Opus 5 Max. Throughput: literature-following routes,
  grindy lanes, statement archives, proof attempts on P1/P2 targets.
- `flash` for lookups and short computations; `consumer` to swallow
  oversized logs. Subagent behavior (build discipline, halt rules,
  no-self-review, no-commit) lives in `.claude/agents/` — do not
  restate it in dispatches beyond the brief.
- Concurrency: up to 10 parallel writer lanes IF write targets are
  pairwise-disjoint. Check `goof sys` for headroom before launching.
  The 4-lane cap from wave 3 was too conservative; wave 3 ran 10
  successfully.

## Build protocol

- Subagents use `timeout 60 lake build <module>` for single-module
  checks (covers ~95% of files). For files needing >60s (heavy
  `decide`, `native_decide` windows), use `timeout 300 lake build`.
- The `flock .lake/agent.lock` protocol from CLAUDE.md serializes all
  agents behind one lock — it is correct for sequential work but
  blocks parallel dispatch. When dispatching >2 concurrent lanes,
  tell agents to use `timeout` instead. When running a single lane,
  `flock` is fine.
- The orchestrator's own verification builds (post-lane, pre-commit)
  should use `flock` since they run alone.

## Dispatch protocol (per lane)

1. Dispatch the brief to the named agent type. One lane = one file =
   one commit (archive batches: one commit per item).
2. The lane halts (done, or halt-never-weaken). It never commits and
   never orders its own review.
3. For high-value lanes (proofs, novel results), dispatch in parallel:
   `vacuity-cop` (rung ladder 1-5) and `reviewer` (style + code).
   For archive cards (sorry'd statements), the orchestrator verifies
   directly (build + surface sweep + axiom check) without full review.
4. Apply fixes yourself (small) or re-dispatch the lane (large). Then
   verify independently before committing:
   - rebuild with `flock .lake/agent.lock lake build <module>`;
   - axiom-sweep: `#print axioms` on every new declaration;
   - grep the new surface for `sorry`, `admit`, `native_decide`,
     `axiom`, `partial def`, `@[implemented_by]`.
5. Commit: one commit per lane, message in repo house style. Never
   push. Then attach subagent provenance via git notes --ref=agents.
6. Update `PLAN.md` and `RESULTS.md` in follow-up doc commits.

## Subagent discipline

- Subagents must NOT post to GitHub, Slack, or any external system.
  Return findings in the final report only.
- Subagents must NOT run `git commit` or `git push`.
- Offer prover handoffs to postdoc lanes that stall — message mid-run
  with a summary template; dispatch a prover continuation if accepted.

- A lane reports failed satisfiability, a false-as-stated goal, or
  proposes reshaping a statement.
- Any security-relevant finding.
- Anything touching gated items: Hough-Nielsen (decision 2), the
  A006285 note (decision 3), Mathlib upstreaming (decision 4), or the
  USER DECISIONS PENDING in PLAN.md.
- A novelty claim beyond what PLAN's PRIOR ART section supports.

## Honesty rails
