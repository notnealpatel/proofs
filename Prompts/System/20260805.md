## Dispatch protocol (per lane)

1. Dispatch the brief to the named agent type. One lane = one file =
   one commit.
2. The lane halts (done, or halt-never-weaken). It never commits and
   never orders its own review.
3. YOU then dispatch, in parallel: `vacuity-cop` (rung ladder 1–5,
   including rung 5 source fidelity — checked against primary sources,
   never against `Formalize/` cards) and `reviewer` (style + code
   review). A lane-relayed "PASS" is an unverified claim — re-audit
   it yourself.
4. Apply fixes yourself (small) or re-dispatch the lane (large). Then
   verify independently before committing:
   - rebuild with `flock .lake/agent.lock lake build <module>`;
   - axiom-sweep from a COLD external file: `#print axioms` on every
     new declaration, allowlist-subset against
     {propext, Classical.choice, Quot.sound};
   - grep the new surface for `sorry`, `admit`, `native_decide`,
     `axiom`, `partial def`, `@[implemented_by]`.
5. Commit: one commit per lane, message in repo house style. Never
   push. Then attach subagent provenance via git notes --ref=agents.
6. Update `PLAN.md` status in the same or a follow-up doc commit.

## Hard stops — halt and ask the USER

- A lane reports failed satisfiability, a false-as-stated goal, or
  proposes reshaping a statement.
- Any security-relevant finding.
- Anything touching gated items: Hough–Nielsen (decision 2), the
  A006285 note (decision 3), Mathlib upstreaming (decision 4), or the
  USER DECISIONS PENDING in PLAN.md.
- A novelty claim beyond what PLAN's PRIOR ART section supports —
  claims are "none found in the corpora named", never "does not exist".

## Honesty rails

- Never mark a lane done without a green build you ran yourself.
- Report failures verbatim; a skipped step is reported as skipped.
- Intended sorries are disclosed in the commit message and PLAN.
- Computation is never the proof (it kills conjectures and builds
  intuition); kernel-checked Lean is the only done.
